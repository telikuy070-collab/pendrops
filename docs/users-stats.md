# Статистика пользователей в админке

Три разных вопроса — три разных ответа. Ни один из них нельзя выдать за другой.

| Вопрос                                                                   | Чем меряется               | Точность                        | Нужен SQL |
| ------------------------------------------------------------------------ | -------------------------- | ------------------------------- | --------- |
| Сколько человек **онлайн прямо сейчас**                                  | Supabase Realtime Presence | точно, в реальном времени       | **нет**   |
| Сколько **разных устройств** открывали приложение за 7 / 30 дней и всего | таблица `app_visits`       | точно, пока таблица установлена | **да**    |
| Сколько **учеников реально учатся**                                      | —                          | не считается в принципе         | —         |

Приложение анонимное: аккаунтов нет, авторизации нет. Поэтому «пользователь»
здесь — это устройство, и все три цифры считают устройства, а не людей.

## 1. «Сейчас онлайн» — работает сразу, ничего применять не нужно

Каждое устройство, открывшее админку, поднимает Realtime-канал `pendrops:presence:v1`
и отдаёт своё присутствие с анонимным `deviceId` (случайный UUID в `localStorage`).
Счётчик — число различных присутствий прямо сейчас; он обновляется сам и не
перезапрашивает базу.

Ничего в схеме базы для этого не меняется: Presence живёт в Realtime-сервере.
Канал открытый (не `private`), читается тем же анонимным ключом, что и всё
остальное приложение, и тем же клиентом, что уже подписан на `postgres_changes`.

Канал поднимается **только внутри админки и только после ввода PIN**, а при
закрытии админки закрывается. Обычный ученик не тратит на счётчик ни одного
соединения.

Если соединение отвалилось, админка показывает «Счётчик онлайн недоступен» и не
показывает никакого числа: «никого нет онлайн» и «никто не считает» — это разные
факты.

## 2. «Устройства за период» — требует одного SQL-файла

**Файл для применения:**

```
supabase/migrations/20260929210000_app_visits.sql
```

Такая же копия лежит в `docs/20260929210000_app_visits.sql`.

Применение: Supabase → SQL Editor → вставить файл целиком → Run. Или через CLI.
Повторный запуск безопасен.

Что делает файл: создаёт таблицу `public.app_visits` (одна строка на устройство:
`device_id`, `first_seen_at`, `last_seen_at`), индекс на `last_seen_at`, включает
RLS и даёт анонимной роли три политики — чтение для админки и вставка/обновление
своей строки для устройства. Существующие таблицы не затрагиваются.

Что в таблице: **только** анонимный идентификатор устройства и даты. Ни имён, ни
групп, ни телефонов, ни IP. Подробности — в шапке самого SQL-файла.

### Пока таблица не установлена

Приложение работает ровно как раньше:

- ученик ничего не замечает — запись визита уходит «fire-and-forget», её падение
  ничего не ломает и не пишет в консоль;
- админка вместо трёх чисел показывает одну строку
  «Статистика за период требует установки таблицы (см. инструкцию)»;
- приложение **не пытается создать таблицу** само.

Как только таблица появится, счётчик заработает сам — переустанавливать сборку не
нужно.

## 3. Откат

```sql
drop table if exists public.app_visits;
```

Счётчик онлайна (пункт 1) от этого не перестанет работать: он базы не касается.
